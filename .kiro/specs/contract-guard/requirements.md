# Requirements Document: ContractGuard

## Introduction

ContractGuard is an AI-powered contract analysis tool designed to help Indian small businesses, freelancers, and solopreneurs understand and evaluate contracts without expensive legal counsel. The system analyzes uploaded contracts, identifies risks, and provides plain-language explanations in Hindi and English, with compliance checks against Indian Contract Law.

## Glossary

- **System**: The ContractGuard application
- **User**: Small business owner, freelancer, or solopreneur in India
- **Contract**: A legal document uploaded by the User for analysis
- **Risk_Score**: A numerical value (1-10) indicating the severity of risk in a contract or clause
- **Risk_Category**: One of four categories: Financial Risk, Legal Liability, IP Concerns, or Termination Risk
- **Clause**: A distinct section or provision within a Contract
- **Analysis_Report**: The complete output generated by the System after analyzing a Contract
- **AWS_Service**: Amazon Web Services components (Textract, Comprehend, Bedrock, S3, Lambda, etc.)
- **Indian_Contract_Act**: The Indian Contract Act, 1872 - the primary legislation governing contracts in India

## Requirements

### Requirement 1: Contract Upload

**User Story:** As a User, I want to upload contract documents, so that I can have them analyzed for risks and compliance issues.

#### Acceptance Criteria

1. WHEN a User drags a PDF file onto the upload area, THE System SHALL accept the file and display upload progress
2. WHEN a User selects a PDF file through the file picker, THE System SHALL accept the file and display upload progress
3. IF a file exceeds 10MB in size, THEN THE System SHALL reject the upload and display an error message
4. IF a file is not in PDF format, THEN THE System SHALL reject the upload and display an error message
5. WHEN a file upload is in progress, THE System SHALL display a progress indicator showing percentage completion
6. WHEN a file upload completes successfully, THE System SHALL store the file in S3 and initiate analysis

### Requirement 2: Text Extraction

**User Story:** As a User, I want the system to extract text from my contract PDF, so that the content can be analyzed.

#### Acceptance Criteria

1. WHEN a Contract is uploaded, THE System SHALL extract all text content using Amazon Textract
2. WHEN text extraction completes, THE System SHALL preserve the document structure including paragraphs and sections
3. IF text extraction fails, THEN THE System SHALL retry up to 3 times before reporting an error
4. WHEN text extraction succeeds, THE System SHALL pass the extracted text to the entity identification component

### Requirement 3: Entity Identification

**User Story:** As a User, I want the system to identify key entities in my contract, so that I can quickly understand the parties, dates, and amounts involved.

#### Acceptance Criteria

1. WHEN extracted text is available, THE System SHALL identify party names using Amazon Comprehend
2. WHEN extracted text is available, THE System SHALL identify dates using Amazon Comprehend
3. WHEN extracted text is available, THE System SHALL identify monetary amounts using Amazon Comprehend
4. WHEN entities are identified, THE System SHALL associate each entity with its location in the Contract
5. WHEN entity identification completes, THE System SHALL pass the results to the clause analysis component

### Requirement 4: Clause Analysis

**User Story:** As a User, I want the system to analyze individual clauses in my contract, so that I can understand what each section means and identify potential risks.

#### Acceptance Criteria

1. WHEN extracted text and entities are available, THE System SHALL analyze clauses using Amazon Bedrock with Claude model
2. WHEN analyzing clauses, THE System SHALL detect unfair liability provisions
3. WHEN analyzing clauses, THE System SHALL detect hidden fees or unexpected costs
4. WHEN analyzing clauses, THE System SHALL detect termination conditions
5. WHEN analyzing clauses, THE System SHALL detect intellectual property ownership provisions
6. WHEN analyzing clauses, THE System SHALL detect non-compete restrictions
7. WHEN clause analysis completes, THE System SHALL generate Risk_Scores for each identified risk pattern

### Requirement 5: Risk Scoring

**User Story:** As a User, I want each risk in my contract to be scored numerically, so that I can prioritize which issues to address first.

#### Acceptance Criteria

1. WHEN a financial risk is identified, THE System SHALL assign a Risk_Score between 1 and 10 based on severity
2. WHEN a legal liability risk is identified, THE System SHALL assign a Risk_Score between 1 and 10 based on severity
3. WHEN an IP concern is identified, THE System SHALL assign a Risk_Score between 1 and 10 based on severity
4. WHEN a termination risk is identified, THE System SHALL assign a Risk_Score between 1 and 10 based on severity
5. WHEN all individual risks are scored, THE System SHALL calculate an overall Risk_Score as the weighted average across all Risk_Categories
6. THE System SHALL categorize Financial Risk based on payment terms, hidden fees, and penalties
7. THE System SHALL categorize Legal Liability based on indemnification clauses, warranties, and liability caps
8. THE System SHALL categorize IP Concerns based on ownership provisions, licensing terms, and confidentiality requirements
9. THE System SHALL categorize Termination Risk based on notice periods and termination conditions

### Requirement 6: Plain Language Translation

**User Story:** As a User, I want legal jargon translated into simple language, so that I can understand my contract without legal training.

#### Acceptance Criteria

1. WHEN a Clause contains legal terminology, THE System SHALL generate a plain-language explanation in English
2. WHEN a Clause contains legal terminology, THE System SHALL generate a plain-language explanation in Hindi
3. WHEN generating explanations, THE System SHALL highlight concerning provisions
4. WHEN generating explanations, THE System SHALL explain implications specifically for small businesses
5. THE System SHALL use Amazon Bedrock to generate culturally appropriate explanations for Indian Users

### Requirement 7: Indian Contract Law Compliance

**User Story:** As a User, I want my contract checked against Indian law, so that I know if any provisions are legally problematic or unenforceable.

#### Acceptance Criteria

1. WHEN analyzing a Contract, THE System SHALL check clauses against the Indian_Contract_Act
2. WHEN a Clause violates the Indian_Contract_Act, THE System SHALL flag the Clause as non-compliant
3. WHEN a Clause specifies jurisdiction outside India, THE System SHALL flag potential jurisdiction issues
4. WHEN compliance checking completes, THE System SHALL include compliance findings in the Analysis_Report

### Requirement 8: Risk Dashboard Display

**User Story:** As a User, I want to see a visual dashboard of risks in my contract, so that I can quickly understand the overall risk profile.

#### Acceptance Criteria

1. WHEN analysis completes, THE System SHALL display an overall Risk_Score prominently
2. WHEN analysis completes, THE System SHALL display a breakdown chart showing Risk_Scores for each Risk_Category
3. WHEN analysis completes, THE System SHALL display a clause-by-clause analysis with individual Risk_Scores
4. WHEN a User views the dashboard, THE System SHALL provide negotiation recommendations for high-risk clauses
5. WHEN displaying risk visualizations, THE System SHALL use color coding (green for low risk, yellow for medium risk, red for high risk)

### Requirement 9: Report Generation

**User Story:** As a User, I want to download a PDF report of the analysis, so that I can share it with others or keep it for my records.

#### Acceptance Criteria

1. WHEN a User requests a report download, THE System SHALL generate a PDF containing the complete Analysis_Report
2. WHEN generating a report, THE System SHALL include the overall Risk_Score
3. WHEN generating a report, THE System SHALL include Risk_Category breakdowns
4. WHEN generating a report, THE System SHALL include clause-by-clause analysis with plain-language explanations
5. WHEN generating a report, THE System SHALL include compliance findings
6. WHEN generating a report, THE System SHALL include negotiation recommendations
7. WHEN report generation completes, THE System SHALL provide a download link to the User

### Requirement 10: User Authentication

**User Story:** As a User, I want to create an account and log in securely, so that my contract analyses are private and accessible only to me.

#### Acceptance Criteria

1. WHEN a User registers, THE System SHALL create an account using Amazon Cognito
2. WHEN a User logs in with valid credentials, THE System SHALL authenticate the User and grant access
3. IF a User provides invalid credentials, THEN THE System SHALL reject the login attempt and display an error message
4. WHEN a User is authenticated, THE System SHALL associate uploaded Contracts with that User's account
5. WHEN a User accesses the System, THE System SHALL only display Contracts and Analysis_Reports belonging to that User

### Requirement 11: File Storage and Retrieval

**User Story:** As a User, I want my uploaded contracts stored securely, so that I can access previous analyses without re-uploading.

#### Acceptance Criteria

1. WHEN a Contract is uploaded, THE System SHALL store the file in Amazon S3
2. WHEN storing a Contract, THE System SHALL encrypt the file at rest
3. WHEN a User requests a previously analyzed Contract, THE System SHALL retrieve it from S3
4. WHEN storing files, THE System SHALL organize them by User account to ensure privacy
5. THE System SHALL generate pre-signed URLs for secure file access with expiration times

### Requirement 12: Frontend Hosting and Delivery

**User Story:** As a User, I want to access the application through a web browser with fast load times, so that I can analyze contracts from anywhere.

#### Acceptance Criteria

1. THE System SHALL host the React frontend application on Amazon S3
2. THE System SHALL serve the frontend through Amazon CloudFront for global content delivery
3. WHEN a User accesses the application URL, THE System SHALL load the frontend within 3 seconds
4. THE System SHALL support HTTPS connections for secure communication
5. THE System SHALL be accessible from modern web browsers (Chrome, Firefox, Safari, Edge)

### Requirement 13: API Gateway and Lambda Integration

**User Story:** As a developer, I want a scalable serverless backend, so that the system can handle varying loads without manual infrastructure management.

#### Acceptance Criteria

1. THE System SHALL expose backend functionality through AWS API Gateway
2. THE System SHALL implement business logic using AWS Lambda functions
3. WHEN an API request is received, THE System SHALL route it to the appropriate Lambda function
4. WHEN a Lambda function executes, THE System SHALL return responses within 30 seconds
5. THE System SHALL handle concurrent requests without degradation up to AWS Free Tier limits

### Requirement 14: AWS Free Tier Compliance

**User Story:** As a project stakeholder, I want the system to operate within AWS Free Tier limits, so that we can demonstrate the solution cost-effectively for the competition.

#### Acceptance Criteria

1. THE System SHALL monitor AWS service usage to stay within Free Tier limits
2. WHEN approaching Free Tier limits, THE System SHALL log warnings
3. THE System SHALL use Amazon Bedrock within the free tier allocation
4. THE System SHALL use Amazon Textract within the free tier allocation
5. THE System SHALL use Amazon Comprehend within the free tier allocation
6. THE System SHALL use S3 storage within the free tier allocation (5GB)
7. THE System SHALL use Lambda execution within the free tier allocation (1M requests/month)

### Requirement 15: Error Handling and User Feedback

**User Story:** As a User, I want clear error messages when something goes wrong, so that I understand what happened and what to do next.

#### Acceptance Criteria

1. IF any AWS_Service fails, THEN THE System SHALL display a user-friendly error message
2. WHEN an error occurs, THE System SHALL log detailed error information for debugging
3. IF analysis fails, THEN THE System SHALL allow the User to retry the operation
4. WHEN displaying errors, THE System SHALL avoid exposing technical implementation details
5. IF a Contract cannot be processed, THEN THE System SHALL explain why and suggest corrective actions
